# Claude Code Remote Control完全ガイド｜どこでもAI作業を続ける5つの活用シーンと設定方法

「PCを離れたら作業も止まる」——そんな常識を覆す機能が、**Claude Code Remote Control**です。

自宅のPCで起動したAIセッションを、スマートフォンのアプリや別のブラウザからそのまま操作できます。しかも、処理はすべてローカルマシン上で動き続けるため、ファイルアクセスもツール設定も変わりません。

この記事では、Remote Controlの具体的な活用シーン5つと、詳細な設定方法をまとめました。

---

## Remote Controlが解決する「あるある」な困りごと

### 困りごと①：長時間タスクのためにPCに張り付かなければならない

テスト実行、大規模なリファクタリング、ドキュメント生成——完了まで時間のかかる作業中、ずっとPCの前にいなければならないのは非効率です。

→ Remote Controlがあれば、作業を走らせたままソファや別の部屋に移動できます。

### 困りごと②：外出先で「あの確認だけしたかった」が叶わない

電車の中や外出中に「さっきのコード、あの変数名どうだっけ」と思っても、帰るまで確認できない。

→ スマホのClaudeアプリを開けば、ローカルのファイルにアクセスしたままClaude に質問できます。

### 困りごと③：別のデバイスに環境を再構築するのが面倒

タブレットで作業しようと思っても、ツールの設定やMCPサーバーの接続を一からやり直すのは手間がかかります。

→ Remote Controlは既存のローカル環境をそのまま共有するため、再構築は不要です。

## 5つの活用シーン

### シーン①：長時間タスクをスマホで監視する

```bash
claude remote-control --name "テスト実行中"
```

このコマンドでサーバーモードを起動し、テストや処理を走らせたまま席を外せます。スマホで進捗確認し、Claudeから「完了しました」の通知を受け取れます。

**ポイント**：`/config` でプッシュ通知をオンにすると、タスク完了時にスマホへ通知が届きます。

---

### シーン②：会議中にコードレビューを続ける

```bash
claude --remote-control "レビュー作業"
```

PCでレビューを開始し、`--remote-control` フラグを付けると会議室のタブレットや別のPCからも同じセッションを操作できます。会議の合間に少し確認する、といった使い方に向いています。

---

### シーン③：既存の会話をそのまま引き継ぐ

Claude Codeをすでに使っている途中で、急にリモート接続したくなった場合：

```
/remote-control
```

このコマンド一つで、現在の会話履歴ごとリモートセッションが開始します。新しいセッションを立ち上げ直す必要はありません。

---

### シーン④：複数のセッションを並行管理する（サーバーモード）

```bash
claude remote-control --spawn worktree --capacity 5
```

`--spawn worktree` オプションを使うと、リモートから接続するたびに独立したgit worktreeが作成されます。複数のタスクを並行して進めたいときに便利です。

| オプション | 動作 |
|---|---|
| `--spawn same-dir`（デフォルト）| すべてのセッションが同じディレクトリを共有 |
| `--spawn worktree` | セッションごとに独立したworktreeを作成 |
| `--spawn session` | 1セッションのみ受け付ける専有モード |

---

### シーン⑤：VS Codeから起動する

VS Codeの拡張機能でも`/remote-control`コマンドが使えます（Claude Code v2.1.79以降）。

入力欄に `/remote-control` と入力するか、`/` メニューから選択すると、バナーに接続ステータスが表示されます。**Open in browser** をクリックするとセッションに直接アクセスできます。

## よくあるエラーと対処法

### 「Remote Control requires a claude.ai subscription」

claude.aiアカウントでログインできていません。

```bash
claude auth login
```

を実行し、claude.aiオプションを選択してください。`ANTHROPIC_API_KEY` が環境変数に設定されている場合は、いったん解除してから再試行します。

---

### 「Remote Control is disabled by your organization's policy」

4つの原因が考えられます：

1. **APIキーでログインしている** → `/login` でclaudeでアカウントに切り替え
2. **TeamまたはEnterpriseプランで管理者が未有効化** → 管理者に `claude.ai/admin-settings/claude-code` での有効化を依頼
3. **データ保持ポリシーの制約** → Anthropicサポートに問い合わせ
4. **デバイスのITポリシー** → `disableRemoteControl` の設定を確認

---

### 「Remote credentials fetch failed」

認証情報の取得に失敗しています。詳細を確認するには：

```bash
claude remote-control --verbose
```

主な原因：ログインしていない、ファイアウォールがポート443をブロックしている、サブスクリプションが失効しているなど。

---

## 全セッションで自動的にRemote Controlを有効にする方法

毎回コマンドを打たずに、すべてのインタラクティブセッションでRemote Controlをオンにしたい場合：

```
/config → Enable Remote Control for all sessions → true
```

または、Desktopアプリの場合は `Settings → Claude Code → Enable remote control by default` から設定できます。

---

## 注意すべき制限事項

- **ローカルプロセスを止めたらセッションも終了**：ターミナルやVS Codeを閉じるとセッションは終わります
- **ネットワーク障害が約10分続くとタイムアウト**：復帰後は `claude remote-control` で再起動が必要
- **Ultraplanとの同時使用不可**：Ultraplanセッション開始時にRemote Controlは切断されます
- **`/mcp`、`/plugin`、`/resume` はローカルCLIからのみ操作可能**

---

## まとめ：Remote Controlの選び方

| 目的 | 推奨の使い方 |
|---|---|
| 進行中の作業を別デバイスで引き継ぐ | `claude --remote-control` |
| 複数のリモートセッションを管理する | `claude remote-control` (サーバーモード) |
| 既存セッションを後からリモートに切り替える | `/remote-control` コマンド |
| VS Codeから使う | 拡張機能の `/remote-control` コマンド |

Remote Controlは「どこにいてもローカル環境のまま作業できる」という、今までのAI開発ツールにはなかった体験を実現します。セットアップはたった一つのコマンドで完了するため、まずは `claude remote-control` を試してみてください。
